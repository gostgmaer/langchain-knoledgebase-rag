## 4. Findings

### F1 - `eslint .` now reports 3 real errors, where the 2026-09-25 report recorded 0 (Low, regression)

`docs/QA_REPORT.md`'s B11 (closed) states "frontend `tsc` and `eslint` now report 0 problems." That's
no longer true as of this commit:

- **`src/app/[role]/settings/page.tsx:82`** — `react-hooks/set-state-in-effect`: a `useEffect` calls
  `setProfileDraft(...)` synchronously as soon as `profileQuery.data` resolves, to seed the edit form
  from the fetched profile. This is a real anti-pattern (an extra render every time the profile query
  resolves, flagged by the newer eslint-plugin-react-hooks rule), not a crash — the page still works,
  but this is exactly the kind of cascading-render source worth fixing before it compounds with
  something else on the same page.
- **`src/app/[role]/team/page.tsx:123,125`** — `react/no-unescaped-entities`: two literal apostrophes
  in `doesn't` inside JSX text content, needing `&apos;`/`&rsquo;` escaping. Cosmetic, not a runtime
  bug — the rendered text is correct either way — but it is a real, currently-failing lint rule.

Neither blocks `tsc` or the build; `vitest` doesn't touch either file. Worth a follow-up fix, but low
severity — recorded here rather than fixed in this pass, since this session's job was to test and
report, not to make unrelated code changes.

(Pre-existing, not new: 5 warnings — 3 unused-`catch`-variable warnings in `public/widget.js`, 1
`no-img-element` warning in `docs-markdown.tsx` for the intentional dashed-border image-placeholder
pattern `docs/BUGS.md` item 50 already documents, 1 unused-eslint-disable warning in a generated
coverage file.)

### F2 - The frontend dev server was already running on an unexpected port (Info, not a bug)

`npm run dev` defaults to port 3000, but a real, working Next.js 16 dev server was already running on
**port 3100** (PID 15548) from an earlier session — not the stray process actually bound to port 3000
(a different, unrelated `node` process that answers every request with `400 WebSockets request was
expected`, i.e. not this app at all). Anyone testing locally should check `netstat`/`Get-NetTCPConnection`
for the real port before assuming `:3000` is where the app is. Left both processes untouched — neither
belongs to this QA pass to manage.
